# 질문 한도, 힌트 대가, 점수 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 사용 횟수 한도 40(질문 1, 추리 5), 사용 10·20·30에서 열리는 힌트와 앞당겨 받는 힌트, 40 뒤 마지막 추리 기회, `100 − 사용 + 보너스×10` 점수를 백엔드가 계산하고 화면이 막대와 점수로 보여 준다.

**Architecture:** 백엔드 `Game`이 `used` 하나로 모든 규칙을 계산한다(열린 힌트 수 = `min(힌트 수, used / 10)`). 질문·추리·힌트·포기 API가 모두 `GameView`를 돌려주고, 화면은 그 값만 그린다. AI 서버는 바뀌지 않는다.

**Tech Stack:** Spring Boot 4 + JUnit + MockMvc (`backend/`), React + Vitest + Testing Library (`frontend/`)

**Spec:** `docs/superpowers/specs/2026-11-24-scoring-design.md`

## Global Constraints
- 상수: 한도 `40`, 추리 비용 `5`, 힌트 간격 `10`. 백엔드 `Game`에만 둔다.
- 열린 힌트 수는 저장하지 않고 `min(scenario.hints().size(), used / 10)`으로 계산한다.
- 질문은 `used < 40`일 때만. 추리는 `used < 40`이면 `used = min(40, used + 5)`, `used == 40`이면 횟수를 쓰지 않는 마지막 추리(틀리면 `FAILED`).
- 힌트 받기: `used = (열린 힌트 수 + 1) × 10`. 남은 힌트가 없으면 409.
- 점수는 끝난 게임에서만: `SOLVED`면 `100 − used + 10 × 맞힌 보너스 수`, 그 밖은 0.
- 판정 요청이 실패하면 `used`는 바뀌지 않는다.
- 화면 문구(그대로 쓴다): `힌트 받기 (사용 N으로)`, `추리는 사용 5를 씁니다.`, `이 추리는 횟수를 쓰지 않습니다.`, `질문을 모두 썼습니다. 마지막 추리 기회가 한 번 남았습니다.`, 판정 도장 `해결` / `실패` / `미해결 종결`, 점수 계산 줄 `100 − 사용 23 + 보너스 10 = 87`.
- 사용자에게 보이는 문장과 주석은 한국어.

## Review Focus
- 사용 39에서 질문 → 40, 이어서 질문은 409, 추리는 가능 (Task 1 테스트)
- 사용 38에서 추리 오답 → 40에서 멈추고 마지막 기회 남음, 이어서 오답이면 `FAILED`·0점 (Task 1 테스트)
- 질문 하나로 힌트가 열림(사용 9 → 10) → 응답 `GameView`의 `hints`에 힌트 1 (Task 1 테스트)
- 판정 오류 때 `used`가 늘지 않음 (Task 1 테스트)
- 힌트가 시나리오에 3개보다 적은 경우 `hintSteps`도 그만큼만 (Task 1 테스트, 가짜 시나리오 없이 계산 함수로 확인)

### Task 1: 백엔드 규칙과 API

**Files:**
- Modify: `backend/src/main/java/com/seaturtle/office/game/Game.java`, `GameStatus.java`, `GameService.java`, `GameController.java`, `GameDtos.java`
- Test: `backend/src/test/java/com/seaturtle/office/GameFlowTests.java`, Create: `backend/src/test/java/com/seaturtle/office/GameRulesTests.java`

**Interfaces:**
- Produces: `GameStatus { PLAYING, SOLVED, GAVE_UP, FAILED }`
- Produces: `Game.LIMIT = 40`, `Game.GUESS_COST = 5`, `Game.HINT_STEP = 10`; `int used()`, `int hintsOpen()`, `boolean finalChance()`, `Integer nextHintAt()`(없으면 null), `List<Integer> hintSteps()`, `int score()`(끝나지 않았으면 0), `int bonusPoints()`
- Produces: `Game.addQuestion(String, Answer)`는 한도를 넘으면 `IllegalStateException`(→ 409). `Game.useHint()`는 `used`를 다음 힌트 자리로 올린다.
- Produces: `GameView`에 `int used, int limit, List<Integer> hintSteps, boolean finalChance, Integer nextHintAt` 추가, `hints`는 열린 힌트 목록. `Reveal`에 `int score, int bonusPoints` 추가.
- Produces: `POST /api/games/{id}/questions` → `GameView`.

- [ ] **Step 1: 실패하는 테스트** (`GameRulesTests`, 「꼬마의 부탁」, 스텁 판정기는 기존 `GameFlowTests.StubJudge`를 패키지 공개로 꺼내 함께 쓴다)
  - `questionsCostOneAndOpenHintAtTen`: 질문 9번 → `used 9, hintsOpen 0`; 10번째 질문 → `used 10, hintsOpen 1`, 컨트롤러 응답(MockMvc) `$.hints.length() == 1`, `$.used == 10`.
  - `hintButtonJumpsToNextStep`: 질문 5번 → 힌트 받기 → `used 10, hintsOpen 1`; 질문 3번(13) → 힌트 받기 → `used 20`; `nextHintAt`은 각각 10, 20, 30, 힌트 3개 다 열리면 `null`이고 힌트 받기는 `IllegalStateException`.
  - `guessCostsFiveAndCapsAtForty`: `used 38`에서 오답 추리 → `used 40, finalChance true, status PLAYING`.
  - `questionAtLimitIsRejected`: `used 40`에서 질문 → `IllegalStateException`, MockMvc 409.
  - `finalGuessWrongFails`: `used 40`에서 오답 추리 → `used 40`, `status FAILED`, `score 0`.
  - `scoreOnSolve`: 질문 3번(3) + 정답 추리(+5=8, 스텁은 보너스 1개) → `SOLVED`, `score == 100 - 8 + 10 == 102`, `bonusPoints 10`, `$.reveal.score == 102`.
  - `judgeErrorDoesNotSpend`: 스텁이 예외를 던지는 질문(`"오류"`) → `JudgeException`, `used` 그대로.
  - `hintStepsFollowHintCount`: `Game.hintStepsFor(2) == [10, 20]`, `Game.hintStepsFor(3) == [10, 20, 30]` (정적 계산 함수).
  - 기존 `GameFlowTests`의 `game.hintsUsed()` 단언은 `hintsOpen()`으로, `games.ask` 반환 사용처는 그대로 두되 컨트롤러 응답 테스트(`questionResponseHasNoKeyField`)는 `$.questions[0].answer`로 바꾼다.

```tsx
it('사용 막대와 힌트 자리를 보여 준다', async () => {
  await openGame({ used: 13, limit: 40, hintSteps: [10, 20, 30], nextHintAt: 20, hints: ['h1'] })
  expect(screen.getByText('사용 13 / 40')).toBeTruthy()
  expect(screen.getByRole('progressbar').getAttribute('aria-valuenow')).toBe('13')
  expect(screen.getByRole('button', { name: '힌트 받기 (사용 20으로)' })).toBeTruthy()
})

it('힌트가 다 열리면 힌트 받기 버튼을 숨긴다', async () => {
  await openGame({ used: 30, hintSteps: [10, 20, 30], nextHintAt: null, hints: ['a', 'b', 'c'] })
  expect(screen.queryByRole('button', { name: /힌트 받기/ })).toBeNull()
})

it('마지막 기회에는 질문 탭을 막고 안내를 보여 준다', async () => {
  await openGame({ used: 40, finalChance: true, nextHintAt: null })
  expect(screen.getByText('질문을 모두 썼습니다. 마지막 추리 기회가 한 번 남았습니다.')).toBeTruthy()
  expect((screen.getByRole('tab', { name: '질문하기' }) as HTMLButtonElement).disabled).toBe(true)
  expect(screen.getByText('이 추리는 횟수를 쓰지 않습니다.')).toBeTruthy()
})

it('질문 응답으로 받은 게임 상태로 화면을 바꾼다', async () => {
  const user = userEvent.setup()
  await openGame({ used: 9, nextHintAt: 10 })
  vi.mocked(api.ask).mockResolvedValue({ ...game, used: 10, hints: ['첫 힌트'], nextHintAt: 20,
    questions: [{ no: 1, seq: 1, text: 'q', answer: 'YES' }] })
  await user.type(screen.getByRole('textbox', { name: '질문' }), 'q{Enter}')
  expect(await screen.findByText('첫 힌트')).toBeTruthy()
  expect(screen.getByText('사용 10 / 40')).toBeTruthy()
})

it('진상 공개에서 점수와 계산을 보여 준다', async () => {
  vi.mocked(api.game).mockResolvedValue({ ...game, status: 'SOLVED', used: 23,
    reveal: { truth: 't', keywords: [], bonuses: [], score: 87, bonusPoints: 10 } })
  render(<GamePage gameId="g1" onExit={() => {}} />)
  expect(await screen.findByText('87점')).toBeTruthy()
  expect(screen.getByText('100 − 사용 23 + 보너스 10 = 87')).toBeTruthy()
})

it('실패하면 실패 도장과 0점', async () => {
  vi.mocked(api.game).mockResolvedValue({ ...game, status: 'FAILED', used: 40,
    reveal: { truth: 't', keywords: [], bonuses: [], score: 0, bonusPoints: 0 } })
  render(<GamePage gameId="g1" onExit={() => {}} />)
  expect(await screen.findByText('0점')).toBeTruthy()
  expect(screen.getByText('실패')).toBeTruthy()
})
```

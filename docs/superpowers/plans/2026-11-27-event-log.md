# 구조화 로그와 이벤트 기록 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**목표:** 판정 요청마다 구간별 시간·모델·토큰·결과를 `events` 테이블에 남기고, 두 서버의 로그를 같은 요청 ID로 잇는다.

**구조:** AI 서버가 판정 응답(성공·502 모두)에 `metrics`를 싣는다. 백엔드 `AiJudgeClient`가 이를 `Judge.Metrics`로 읽고,
`GameService`가 전체 시간을 재어 `EventRecorder`로 `events`에 한 줄 쓴다. `RequestIdFilter`가 요청 ID를 MDC·응답 헤더·AI 요청 헤더에 싣는다.

**기술:** Spring Boot 4.2(구조화 로그, JdbcClient, Jackson 3 `tools.jackson`), Flyway, FastAPI, 표준 `logging`, pytest.

**설계 문서:** `docs/superpowers/specs/2026-11-27-event-log-design.md`

## 전체 제약
- 이벤트 종류: `game_started`, `question_asked`, `guess_submitted`, `hint_used`, `game_ended`, `game_reset`. `outcome`: `ok` / `judge_error` / `timeout` / `conflict`.
- 질문·추리 원문은 이벤트 어디에도 넣지 않는다. `text_length`는 strip 뒤 코드 포인트 수.
- 이벤트 기록 실패는 게임 요청을 깨뜨리지 않는다(경고 로그만).
- `app_version`은 `APP_VERSION`, 없으면 `dev`. 가짜 판정기의 모델은 `fake`, 토큰 0.
- 요청 ID: 들어온 `X-Request-Id`가 `^[A-Za-z0-9-]{8,64}$`면 그대로, 아니면 새 UUID. 응답 헤더로 돌려준다.
- 판정 근거(`reason`)는 AI 서버 로그에만. 로그에 API 키·`Set-Cookie`를 찍지 않는다.
- 사용자에게 보이는 글, 커밋 메시지, 문서는 한국어. 커밋 끝에 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- 백엔드 테스트는 Docker 필요. **사용자가 켜 둔 `sea-turtle-office-postgres-1` 컨테이너는 멈추지 않는다.**

## 검토 초점
1. 판정은 됐지만 저장이 409인 질문 → `conflict` 이벤트에 토큰이 남고 `game_ended`는 없다 — Task 5 테스트.
2. AI 서버가 OpenAI 응답 뒤 형식 오류로 502 → 백엔드 이벤트 `judge_error`에 토큰이 남는다 — Task 1·4·5 테스트.
3. 예전 AI 서버(응답에 `metrics` 없음) → 판정은 그대로 되고 이벤트의 지표 칸만 비어 있다 — Task 4 테스트.
4. 이상한 `X-Request-Id`(공백, 너무 김, 줄바꿈) → 새 ID로 바뀌고 로그·헤더에 원문이 새지 않는다 — Task 3 테스트.
5. `events` 테이블 쓰기가 실패해도 질문 요청은 200 — Task 5 테스트.

  - `EventRecorder`(`@Component`): `void record(Event e)` — `JdbcClient`로 INSERT(`?::uuid`, `?::jsonb`). `request_id`는 MDC, `app_version`은 `@Value("${APP_VERSION:dev}")`, `backend_ms = totalMs − metrics.aiMs`(둘 다 있을 때). 예외는 `log.warn("이벤트 기록 실패: {}", type, e)` 후 삼킨다. 서비스에 트랜잭션이 없으므로 INSERT는 자동 커밋(설계의 REQUIRES_NEW와 같은 효과).
  - `GameService`:
    - `start`: 새로 만들었을 때만 `game_started`.
    - `ask`/`guess`: 메서드 시작에 `System.nanoTime()`. 판정 `JudgeException` → `outcome = e.timeout() ? "timeout" : "judge_error"`, `metrics = e.metrics()`로 기록 후 다시 던짐.
      `guess`의 키워드 수 불일치·`story` null 거절은 `new JudgeException(msg, verdict.metrics())`로 던져 같은 경로로 기록.
      저장 `GameConflictException` → `conflict`(answer, 지표 포함) 후 다시 던짐. 성공 → `ok`. 그 뒤 상태가 PLAYING에서 바뀌었으면 `game_ended`.
    - `hint`: 저장 성공 뒤 `hint_used`(`detail {hint: hintsOpen}`). `giveUp`: 저장 성공 뒤 `game_ended`.
    - `reset`: 지우기 전에 판을 읽어(없으면 404) 지운 뒤 `game_reset`(`detail {status, used}`).
    - `game_ended.detail`: `status, grade, used, adjustedUsed, bonusSaved, keywordsFound, keywordTotal, bonusFound, bonusTotal`.
    - 추리 `answer`는 마지막 `GuessRecord.closeness()`, `detail {matched, total, bonus, story}`.

# 결과 페이지 (짧은 설계)

## 의도
지금은 게임이 끝나면 송신 단말 자리 아래에 진상 보고서가 붙는다. 사용자는 이 순간이 "아예 다른 곳으로 넘어가는" 느낌이길 원한다.
그래서 결과는 별도 페이지로 옮기고, 끝난 사건의 사건 기록과 수신 기록도 그 페이지에서 다시 볼 수 있게 한다.

## 사용자 결정
- 게임이 끝나면(정답, 마지막 추리 실패, 포기) **결과 페이지로 넘어간다.**
- 넘어가는 장면은 **A. 신호 단절**이다.
  - 수신 기록 화면에 잡음이 크게 인다.
  - 화면 전체가 꺼지듯 검게 닫힌다.
  - "교신 종료" 한 줄이 뜬 뒤 결과 페이지가 켜진다. 전체 1~2초.
- 결과 페이지 맨 위에는 판정(**사건 해결** / **미해결 종결**)과 점수를 두고, 그 아래에 진상을 둔다.
- 사건 기록과 수신 기록은 **탭을 나누지 않고 한 화면에서 함께 본다.**
- 만드는 방법은 **1. 결과 페이지를 따로 만들기**다.

## 방법 (1안)
- **주소:** 새 주소 `#/game/{id}/result`에 `ResultPage`를 둔다.
- **게임 중에 끝날 때:** 응답의 상태가 PLAYING이 아니게 되면 `GamePage`가 신호 단절 연출을 보여 준 뒤 결과 주소로 바꾼다.
- **이미 끝난 게임으로 들어올 때:** `#/game/{id}`가 이미 끝난 게임이면 연출 없이 바로 결과 주소로 보낸다.
- **반대 경우:** 진행 중인 게임의 결과 주소로 들어오면 게임 화면으로 돌려보낸다.
- **컴포넌트 분리:** `GamePage`의 사건 기록 화면과 수신 기록 화면(사용 막대와 기록 목록 포함)을 컴포넌트로 떼어 낸다. 두 페이지가 함께 쓴다.
- **백엔드:** 바꾸지 않는다. 끝난 게임도 진상과 모든 기록을 이미 내려 준다.
- **움직임 줄이기:** 브라우저가 움직임 줄이기 설정이면 연출 없이 바로 넘어간다.

## 결과 페이지 구성
```
┌ 교신 종료 // 사건 기록 봉인 ────────────────────┐
│ 사건 해결   87점   (100 − 사용 13)               │
│ [진상] [기록]                          목록으로 │
├─────────────────────────────────────────────────┤
│ 진상 탭: 진상 문장, 핵심 키워드, 보너스         │
│ 기록 탭: 사건 기록 │ 수신 기록  (게임 화면과    │
│          같은 50:50 배치, 읽기 전용)             │
└─────────────────────────────────────────────────┘
```
- **판정 색:** 정답은 노란 빛(계시 색), 실패와 포기는 빨간 빛이다. 연출 색도 같다.

## 내가 정한 것
- **탭은 두 개**([진상] [기록])로 한다. 처음 열리면 진상 탭이다.
  - 사용자는 앞서 세 탭에 동의했지만, 이후 사건 기록과 수신 기록을 한 화면에서 보길 원했다. 그래서 둘을 "기록" 탭 하나로 합쳤다.
- **기록 탭(읽기 전용):**
  - 송신 단말과 포기 버튼은 없다.
  - 사용 막대의 열린 계시는 그대로 눌러서 계시창으로 다시 볼 수 있다.
  - 다음 계시 요청 버튼은 없다.
  - 수신 기록의 글자 풀림 연출은 다시 하지 않는다.
- **판정 이름:** SOLVED는 "사건 해결"이다. FAILED와 GAVE_UP은 "미해결 종결"이다.
  - 둘은 서버 상태로 이미 구분된다. 그래서 보조 문구만 다르게 한다. FAILED는 "마지막 추리 실패", GAVE_UP은 "조사 중단"이다.
- **목록으로 버튼:** 결과 페이지 머리에 둔다.

## 바꾸지 않는 것
게임 규칙, 서버, API, 진행 중 게임 화면의 모양과 동작.

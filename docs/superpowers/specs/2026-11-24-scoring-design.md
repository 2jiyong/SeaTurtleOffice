# 질문 한도, 힌트 대가, 점수 (설계)

## 의도
지금은 질문과 추리가 무제한이고, 힌트는 아무 때나 대가 없이 열린다. 그래서 잘 푼 것과 못 푼 것이 구분되지 않는다.
질문 한도를 두고, 질문·추리·힌트가 모두 같은 "사용 횟수"를 쓰게 해서, 적게 쓰고 풀수록 점수가 높아지게 한다.
`docs/backlog.md` 3번이다. 대표 이미지·힌트 이미지는 4번(이미지)과 함께 하고 여기서는 하지 않는다.

## 규칙 (사용자 결정)
- **사용 횟수 한도는 40**이다. 질문 1회 = 1, 추리 1회 = 5.
- **힌트는 사용 10, 20, 30**에서 하나씩 자동으로 열린다(총 3개). 40에는 힌트가 없다.
- **힌트 받기**: 그 전에 버튼을 누르면 다음 힌트가 바로 열리고, 사용 횟수가 그 힌트 자리로 올라간다. 예: 사용 5에서 누르면 10, 사용 13에서 누르면 20.
- **40을 다 쓰면** 질문은 더 할 수 없고, **마지막 추리 기회가 한 번** 남는다. 이 추리는 횟수를 쓰지 않는다. 틀리면 실패로 끝난다.
- **점수**: 해결하면 `100 − 사용 횟수` + 맞힌 보너스 하나에 10점. 실패·포기는 0점(보너스도 없음).
- **화면**: 사용 횟수를 막대 하나로 보여 주고, 질문할 때마다 차오른다. 막대에 10, 20, 30 힌트 자리를 표시한다.

## 하지 않는 것
- 점수 기록·순위표(점수는 게임 끝 화면에만 보인다. 게임 상태는 지금처럼 메모리에만 있다).
- 대표 이미지·힌트 이미지(4번).
- AI 서버 변경. 판정 방식은 그대로다.
- 시나리오마다 다른 한도나 힌트 자리.

## 실패로 보는 것
- 백엔드를 우회해 한도를 넘는 것(API를 직접 불러 41번째 질문, 대가 없는 힌트).
- 새로고침하면 사용 횟수나 열린 힌트가 달라지는 것.
- 힌트 버튼을 누르기 전에 대가를 알 수 없는 것.

## 방법
- **선택: 백엔드가 사용 횟수·힌트·마지막 기회·점수를 모두 계산하고, 화면은 받은 값을 보여 주기만 한다.** 게임 상태가 이미 백엔드에 있고, 새로고침과 API 직접 호출에도 규칙이 지켜진다.
- 뺀 것: 화면이 횟수를 세는 방식. 새로고침하면 어긋나고 한도를 우회할 수 있다.

## 정한 것 (백엔드)
- 상수: 한도 `40`, 추리 비용 `5`, 힌트 간격 `10`.
- `Game`이 `used`(사용 횟수)를 가진다. 열린 힌트 수는 따로 세지 않고 `min(시나리오 힌트 수, used / 10)`으로 계산한다(기존 `hintsUsed` 필드는 없앤다).
- **질문**: `used < 40`일 때만 받는다. 판정 뒤 `used += 1`. `used == 40`에서 질문하면 오류(409, "질문을 모두 썼습니다. 마지막 추리만 남았습니다.").
- **추리**:
  - `used < 40`: `used = min(40, used + 5)`. 정답이면 해결.
  - `used == 40`(마지막 기회): 횟수를 쓰지 않는다. 정답이면 해결, 틀리면 상태 `FAILED`.
  - 사용 38에서 추리하면 40이 되고, 틀리면 마지막 기회가 남는다.
- **힌트 받기**: 다음 힌트가 남아 있으면 `used = (열린 힌트 수 + 1) × 10`. 남은 힌트가 없으면 오류(409). `used`가 이미 그 자리 이상이면 힌트는 이미 열려 있으므로 이 경우는 생기지 않는다.
- 판정(AI 서버 요청)이 실패하면 `used`는 늘지 않는다(지금처럼 판정을 받은 뒤 기록한다).
- **상태**: `GameStatus`에 `FAILED`를 더한다(마지막 추리 실패). 포기는 지금처럼 `GAVE_UP`.
- **점수**: 끝난 게임에서만 계산한다. `SOLVED`면 `100 − used + 10 × 맞힌 보너스 수`, 그 밖은 0.
- **API**:
  - `GameView`에 `used`, `limit`(40), `hintSteps`(힌트가 열리는 자리 목록, 예 `[10, 20, 30]`, 시나리오 힌트 수만큼), `finalChance`(`used == 40`이고 진행 중), `nextHintAt`(힌트 받기를 누르면 올라갈 자리, 남은 힌트가 없으면 `null`)를 더한다.
  - `Reveal`에 `score`, `bonusPoints`(보너스로 더한 점수)를 더한다.
  - `POST /games/{id}/questions`도 `GameView`를 돌려준다(지금은 질문 기록 하나). 질문 하나로 힌트가 열릴 수 있어서 화면이 게임 전체를 다시 받아야 한다.

## 정한 것 (화면)
- 기록지 머리의 "질문 n"을 사용 막대로 바꾼다: "사용 n / 40" + 막대. 막대에 10, 20, 30 눈금과 "힌트1~3" 표시. 이미 열린 힌트 눈금은 다르게 칠한다.
- "힌트 받기" 버튼 이름은 `힌트 받기 (사용 N으로)`. 남은 힌트가 없으면 숨긴다.
- 마지막 기회: 질문 탭을 막고 추리 탭만 남긴다. 입력칸 위에 "질문을 모두 썼습니다. 마지막 추리 기회가 한 번 남았습니다."
- 추리 탭에 "추리는 사용 5를 씁니다."를 작게 적는다(마지막 기회에는 "이 추리는 횟수를 쓰지 않습니다.").
- 진상 공개: 점수를 크게, 그 아래 계산을 한 줄로("100 − 사용 23 + 보너스 10 = 87"). 실패·포기는 "0점". 판정 도장은 해결 "해결", 실패 "실패", 포기 "미해결 종결".

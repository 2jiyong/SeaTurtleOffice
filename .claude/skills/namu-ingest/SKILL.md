# 나무위키 세계관 정리 (namu-ingest)

사용자가 붙여넣은 나무위키 텍스트를 `world/` 세계관 문서에 정리해 넣는다.
붙여넣은 텍스트에는 쓸데없는 내용이 섞여 있고 순서도 뒤죽박죽이라고 가정한다.
**붙여넣은 순서가 아니라, 문서 규격이 정한 위치에** 넣는다.

## 시작 전에 반드시 읽을 것

1. `references/schema.md` — 문서 규격(메타데이터, type, 시대, 베이스 섹션, 본문 형식, ID 규칙). 이 규격이 유일한 기준이다.
2. `world/_todo.md` — 만들어야 할 항목, 확인이 필요한 항목.
3. `world/_sources.md` — 이미 처리한 원문 목록. 같은 문서를 다시 받았는지 확인한다.
4. 기존 항목 목록 — `world/detail/` 아래 파일들의 `id`, `title`, `aliases`를 grep으로 훑어 이미 있는 대상을 파악한다.

## 작업 순서

### 1. 원문 확인
- 어느 나무위키 문서(와 섹션)인지 파악한다. 사용자가 말하지 않았으면 붙여넣은 텍스트의 제목·목차에서 추정하고, 추정이 어려울 때만 묻는다.
- `_sources.md`에 이미 있는 문서면 "다시 받은 문서"로 보고, 바뀌거나 추가된 내용만 반영한다.

### 2. 정제 — 버릴 것
다음은 세계관 문서에 넣지 않는다.
- **나무위키 자체 요소:** 목차, `[편집]`, 각주 번호(`[1]`)와 각주 중 출처 표시뿐인 것, 분류, "상위 문서/하위 문서/관련 문서" 안내, 틀(네비게이션 박스), 문서 상단 경고문, 역링크 안내
- **게임 공략·시스템 정보:** 스탯, 수치, 스킬 계수, 덱·편성, 획득 방법, 가챠, 티어 평가, 공략 팁, 패치 내역
- **외부 정보:** 성우, 개발 비화, 출시일, 매출, 커뮤니티 반응·평가, 밈과 드립, 취소선 농담, 2차 창작, 여담 중 세계관과 무관한 것
- **팬 추측:** 근거 없는 추측과 "~라는 해석이 있다"류. 원작 묘사에 근거한 해석이면 `certainty: inferred`로 남길 수 있다.

판단 기준: **"이 세계 안에서 사실인가?"** 그렇다면 남기고, 게임 바깥 이야기라면 버린다.
게임 시스템처럼 보여도 세계 안의 설정이면 남긴다(예: 인격·E.G.O의 수치는 버리지만, 그것이 세계관에서 무엇인지에 대한 설명은 남긴다).

애매한 각주는 내용을 보고 판단한다. 각주 안에 설정 정보가 들어 있는 경우가 많다.

### 3. 사실 단위로 분해
남은 내용을 **사실 하나 = 한 문장**으로 쪼갠다. 각 사실에 대해 정한다.
- **대상:** 이 사실이 무엇에 관한 것인가 (항목 후보)
- **시대:** 언제 사실인가 (`all` 또는 시대 ID)
- **확실성:** `official` / `inferred` / `unknown`

### 4. 배치 결정
각 사실을 어디에 넣을지 정한다.
- **상세 항목:** 모든 사실의 원본은 상세 항목에 둔다(하나의 사실은 한 곳에만).
- **베이스:** 그 사실이 ① 작품 공통이고 ② 시대와 무관하고 ③ 도시 전반의 개념이고 ④ `official`이면, 베이스 해당 섹션에 **요약으로** 반영하고 그 섹션의 `sources`에 상세 항목 ID를 추가한다. 개별 대상(특정 날개, 특정 협회, 특정 인물)의 세부 사항은 베이스에 넣지 않는다.
- **시대 구분:** 시대의 시작·끝 사건이나 "이 시대에 새로 참이 된 것/더 이상 참이 아닌 것"에 해당하면 `world/base/08-eras.md`에도 반영한다.

### 5. 기존 항목에 병합 또는 새 항목 생성
- 대상의 정식 명칭과 별칭으로 기존 항목을 찾는다(`title`, `aliases` grep).
- **있으면 병합:** 없는 사실만 추가한다. 이미 있는 사실과 같은 내용이면 넣지 않는다. 새 별칭은 `aliases`에 추가한다. `updated`를 오늘 날짜로 바꾼다.
- **없으면 생성:** schema.md의 ID·경로 규칙과 템플릿으로 새 파일을 만든다.
- **`_todo.md`의 "만들어야 할 항목"에 있던 대상이면** 만든 뒤 목록에서 지운다.

### 6. 분할
- 본문이 약 800자를 넘으면 하위 항목으로 나누고 하위 항목에 `parent`를 적는다.
- 같은 대상이라도 시대에 따라 상태가 다르면 시대별 하위 항목으로 나눈다. 서로 모순되는 사실을 한 항목에 섞지 않는다.

### 7. 연결
- 내용상 연결된 항목을 `related`에 적는다.
- 아직 없는 항목이면 schema.md 규칙대로 ID를 미리 정해 `related`에 넣고, `_todo.md`의 "만들어야 할 항목"에 추가한다.

### 8. 충돌 처리
- 새 내용이 기존 항목과 다르면 **덮어쓰지 않는다.** 기존 내용을 유지하고 `_todo.md`의 "확인 필요"에 두 주장과 각각의 출처를 적는다.
- 붙여넣은 내용이 내가 알고 있는 설정과 다르게 보여도 고치지 않는다. 보고에서 언급만 한다.

### 9. 기록
- `_sources.md`에 처리한 원문(문서명, 섹션, 날짜, 영향받은 항목 ID)을 추가한다.
- 공통 용어의 대표 표기가 새로 정해지면 `world/base/10-glossary.md`에 추가한다.

### 10. 보고
작업이 끝나면 사용자에게 짧게 보고한다.

```
## 처리 결과: 「문서명」
- 새 항목: id (제목) ...
- 수정한 항목: id — 무엇을 추가했는지 ...
- 베이스 반영: 섹션 — 무엇을 ...
- 버린 내용: 공략 수치, 밈 등 (한 줄 요약)
- 확인 필요: 시대 판단이 애매한 것, 공식/해석이 애매한 것, 기존 내용과 충돌한 것
- 만들어야 할 항목에 추가: id ...
```

## 작성 원칙

- **다시 쓴다.** 나무위키 문장을 그대로 옮기지 않고 내 문장으로 요약한다. 고유명사와 짧은 용어 외에는 원문 표현을 복사하지 않는다.
- **붙여넣은 내용만 근거로 쓴다.** 내 기억으로 빈 곳을 채우지 않는다.
- **지시어 대신 고유명사.** "그", "이 조직" 대신 대상 이름을 반복한다. 조각 하나만 검색되어도 뜻이 통해야 한다.
- **단정형으로 쓴다.** "~이다", "~한다". 추측 표현("~인 듯하다")은 `inferred` 항목에서만 쓰고 근거를 적는다.
- **대표 표기만 쓴다.** 본문에서는 각 대상의 `title`(대표 표기)만 쓰고 다른 표기는 `aliases`에 둔다.
- **한국어로 쓴다.**
- 베이스는 AI 프롬프트에 매번 들어가므로 짧게 유지한다. schema.md의 분량 상한을 넘을 것 같으면 보고에서 알린다.
- 메타데이터의 `updated`는 오늘 날짜(YYYY-MM-DD)로 쓴다.

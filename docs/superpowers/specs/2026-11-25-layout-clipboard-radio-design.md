# 화면 배치: 클립보드 사건 기록과 무전기 조작판 (짧은 설계)

## 의도
수신 기록 칸이 너무 크고 사건 기록이 작다. 사건 기록을 키우고, 사건 기록과 입력칸(질문하기·추리 제출)도 주시자 무전 콘셉트에 맞게 바꾼다.
시안: `.superpowers/brainstorm/.../layout.html`의 B(사용자 선택).

## 사용자 결정
- 사건 기록 : 수신 기록 = **50 : 50**.
- **수신 기록 화면 안쪽은 지금 그대로**(바탕, 주사선, 흐르는 띠, 머리, 줄 모양과 색, 연출). 폭만 줄어든다.
- 사건 기록은 **클립보드**(갈색 판, 위쪽 금속 집게, 끼운 서류). 서류 머리 "사건 기록"과 위험 등급, 제목, 대표 이미지(없으면 숨김), 문제, "힌트 요청 (사용 N으로)", "포기하고 진상 보기".
- 수신 기록 바깥에 **무전기 몸체** 테두리, 그 아래 **조작판**: "질문"·"추리" 기계 버튼, 녹색 액정 입력칸, "송신 ▶" 버튼.

## 내가 채운 것
- 좁아진 수신 기록에서 질문과 답이 한 줄에 안 들어가면 답이 질문 아래 오른쪽으로 내려간다(겹치지 않게). 이것 말고 수신 기록 안쪽 스타일은 바꾸지 않는다.
- 추리 모드: 액정이 여러 줄로 커지고 조작판 아래 "추리는 사용 5를 씁니다."
- 마지막 기회: "질문" 버튼 잠김, 액정 위 "질문을 모두 썼습니다. 마지막 추리 기회가 한 번 남았습니다."
- 답을 기다리는 동안: "송신" 버튼이 눌린 모양의 "수신 대기".
- 글자 수·Enter 안내는 조작판 아래 작게.
- 게임이 끝나면 조작판 자리에 지금처럼 진상 공개 보고서.
- 좁은 화면(760px 이하): 지금처럼 위아래로 쌓는다.
- 서류 머리는 "사건 기록"만 쓴다. 게임 화면은 사건 번호(목록 순서)를 모른다(GameView에 없다). 번호를 넣으려면 API를 바꿔야 해서 이번에는 뺀다.

## 바꾸지 않는 것
게임 규칙, 서버, API, 수신 기록 안쪽 스타일, 버튼과 입력의 동작(접근성 이름 "질문하기"·"추리 제출" 탭, "질문" 입력칸 포함).

## 방법
CSS와 화면 구조만 바꾼다. 기존 테스트가 쓰는 접근성 이름(탭 이름, 입력칸 이름, 버튼 이름 규칙)은 유지해서 동작 테스트가 그대로 통과하게 한다. 그래서 바꿀 것은 화면 모양뿐이고 방법은 하나다.

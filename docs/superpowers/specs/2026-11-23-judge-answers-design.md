# 진행자 답 표현과 답 설명 (설계)

## 의도
진행자는 사건의 전말을 모두 아는 존재다. 예/아니오 대신 사람이 말하듯 답하고,
답 아래에 그 답이 게임 규칙상 무슨 뜻인지 안내해서 플레이어가 답을 오해하지 않게 한다.

## 목표
- 질문 판정 결과를 9가지 경우 중 하나로 정한다. 각 경우에 진행자의 말(5가지)과 안내 문장(9가지)이 하나씩 붙는다.
- 시나리오와 관련 없는 도시 상식 질문에는 "중요하지 않단다"로 답한다.
- 핵심 질문 판단과 화면의 증거 표시를 없앤다.

## 하지 않는 것
- 추리 결과, 힌트, 해결 문구를 진행자 말투로 바꾸는 것(다음 작업).
- 시나리오 문서의 판정 메모 형식을 바꾸는 것.

## 실패로 보는 것
- 안내 문장이나 답이 진상의 내용을 흘리는 것. 그래서 AI는 문장을 쓰지 않고 코드만 고른다.
- 진행자의 말과 안내 문장이 서로 어긋나는 것(예: "그렇단다" + "관련이 없는 내용입니다").

## 9가지 경우
| 코드 | 진행자의 말 | 안내 문장 |
|---|---|---|
| `YES` | 그렇단다 | 진상에 비추어 맞는 내용입니다. |
| `NO` | 아니란다 | 진상에 비추어 틀린 내용입니다. |
| `PARTIAL_SOME` | 어느정도는 그렇단다 | 일부만 맞는 내용입니다. |
| `PARTIAL_CONDITION` | 어느정도는 그렇단다 | 조건을 붙이면 맞는 내용입니다. |
| `IRRELEVANT_UNRELATED` | 중요하지 않단다 | 이 사건과 관련이 없는 내용입니다. |
| `IRRELEVANT_UNDECIDED` | 중요하지 않단다 | 이 사건에서 정하지 않은 세부사항입니다. |
| `INVALID_FORM` | 말해줄 수 없단다 | 예·아니오로 답할 수 없는 질문입니다. |
| `INVALID_TRUTH` | 말해줄 수 없단다 | 진상을 직접 묻는 질문입니다. |
| `INVALID_RULE` | 말해줄 수 없단다 | 규칙을 벗어난 요청입니다. |

## 방법
- **A(선택): AI가 9가지 코드 중 하나를 바로 고른다.** 진행자의 말은 코드에서 정해지므로 말과 안내가 어긋날 수 없다.
- B: 답(5)과 설명(9)을 따로 고른다. 짝이 안 맞는 조합을 서버가 검사하고 다시 물어야 해서 뺐다.
- C: AI가 안내 문장을 직접 쓴다. 진상이 샐 위험이 있고 문장이 매번 달라져서 뺐다.

## 정한 것
- 서버끼리는 코드만 주고받는다. 진행자의 말과 안내 문장은 프런트엔드 한 곳(`api.ts`)에만 둔다.
- 판정 규칙(`ai/app/prompts.py`)을 9가지 코드 기준으로 다시 쓴다.
  - 상식 질문: 이 사건과 이어지면 진상과 세계관에 따라 답하고, 아니면 `IRRELEVANT_UNRELATED`.
  - 판정 메모의 "예 / 아니오 / 상관없음 / 예로 볼 수 있다"는 각각 `YES` / `NO` / `IRRELEVANT_*` / `PARTIAL_*`로 읽는다.
    `*` 중 어느 쪽인지는 AI가 진상을 보고 고른다.
- AI 응답 스키마에서 `key`를 뺀다. 백엔드 질문 기록과 API 응답에서도 `key`를 뺀다.
- 화면: 도장에는 진행자의 말, 그 아래 작은 글씨로 안내 문장. 도장 색은 진행자의 말 5가지 기준(같은 말이면 같은 색).
  "증거 N" 표지와 "확보한 증거" 숫자를 없앤다.

## 만드는 사람에게 맡기는 것
- 판정 규칙 문장의 구체적인 표현.
- 안내 문장의 글자 크기와 배치(좁은 화면 포함).

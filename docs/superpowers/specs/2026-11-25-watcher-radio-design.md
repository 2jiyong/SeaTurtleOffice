# 주시자 무전 연출과 이미지 자리 (설계)

## 의도
지금 답은 종이 기록지에 찍히는 도장이라, 진행자가 "모든 것을 아는 존재(주시자)"라는 느낌이 약하다.
주시자의 답과 힌트가 **무전으로 내려오는 것처럼** 보이게 한다. 노이즈가 낀 화면에서 깨진 글자가 맞춰지며 답이 나타난다.
같은 김에 이미지를 넣을 **자리**를 만든다. 그림 자체는 다음 단계에서 만든다. `docs/backlog.md` 2번과 4번이다.

시안: `.superpowers/brainstorm/`의 `radio-answer-v2.html`(오른쪽 "어두운 수신 화면"), `code-made-elements.html`.

## 사용자 결정
- 오른쪽 기록지를 **어두운 수신 화면**으로 바꾼다. 왼쪽 사건 기록은 종이 그대로.
- 답은 질문 **오른쪽**에, 깨진 글자가 섞이다가 맞춰지고 빨강·파랑으로 잠깐 어긋났다가 자리 잡는다(시안 C의 느낌).
- 계속 깔리는 지지직 노이즈는 **쓰지 않는다**(눈이 아프다). 위에서 아래로 천천히 흐르는 **밝은 띠는 쓴다**.
- 결과 도장(해결·실패·미해결 종결)은 시안대로.
- **주시자 로고는 A(눈)**. 질문하는 곳(수신 기록 머리)에만 둔다.
- **사이트 상징은 따로** 만든다(머리말 로고·탭 아이콘). 그림으로 만들 수 있다. 그 전까지는 지금 육각형.
- **힌트도 무전으로** 수신 기록에 들어온다.

## 내가 채운 것 (사용자 확인)
- 아주 옅은 주사선(움직이지 않음)은 남긴다. 화면 전체 흔들림은 뺀다.
- 수신 기록 제목은 "수신 기록", 머리에 깜빡이는 "주시자와 연결됨" 신호.
- 기다리는 동안 "판정 중" 도장 대신 깨진 글자의 "수신 중"이 깜빡인다.
- 힌트 줄 이름은 "계시 N". 열린 순간의 자리(질문·추리 사이)에 끼워 들어가고, 답과 같은 일그러짐으로 나타난다. 힌트 이미지가 있으면 그 줄 안에 보인다.
- 왼쪽 사건 서류의 노란 힌트 메모는 뺀다. 문제, 대표 이미지, 힌트 받기, 포기만 남는다.
- 추리가 정답이면 "모두 맞혔구나."(진행자 말투). 오답은 지금처럼 "핵심 n/m" + 빠졌을 때 문장.
- 게임 안내(마지막 기회, 추리 비용 등)는 지금처럼 "~입니다".

## 하지 않는 것
- 그림 만들기(배경, 사이트 상징, 기본 표지, 문제별 그림). 자리만 만든다.
- AI 판정 방식, 점수 규칙.
- 진행자가 문장을 생성하는 연출(그러면 SSE가 필요해진다).

## 실패로 보는 것
- 눈이 피로한 움직임(계속 깜빡이는 노이즈, 화면 흔들림).
- 새로고침할 때마다 지난 답이 전부 다시 일그러지는 것. 일그러짐은 **새로 들어온 줄에만** 한 번.
- 움직임 줄이기 설정을 켠 사용자에게도 일그러짐이 나오는 것.
- 그림 파일이 없을 때 화면이 깨지는 것. 없으면 지금처럼 글자만 보인다.

## 방법
하나다. **백엔드가 힌트가 열린 순서(`seq`)를 기록하고, 화면이 질문·추리·힌트를 `seq` 순으로 수신 기록에 늘어놓는다.**
지금 힌트는 "열린 개수"로만 계산해서, 언제 열렸는지(어느 질문 다음인지) 알 수 없다. 화면이 짐작하면 새로고침 때 위치가 바뀐다.

## 정한 것 (백엔드)
- `Game`이 힌트가 열릴 때마다 `HintRecord(int no, int seq, String text, String image)`를 남긴다. 사용 횟수가 10·20·30을 넘는 순간(질문·추리·힌트 받기 어느 쪽이든) 그 시점의 `seq`로 기록한다. 한 번에 두 개를 넘으면(예: 사용 8에서 추리로 13이 되면 하나, 18에서 23이면 하나) 넘은 개수만큼 순서대로 기록한다.
- `GameView.hints`를 `List<HintRecord>`로 바꾼다(지금은 문자열 목록).
- **이미지 파일**: `scenarios/images/<slug>/` 아래 `cover`, `hint-1`, `hint-2`, `hint-3`. 확장자는 `webp`, `png`, `jpg` 순으로 찾는다. 요청할 때마다 파일이 있는지 본다(서버를 다시 켜지 않아도 넣은 그림이 보이게).
- `GET /api/scenarios/{slug}/images/{name}`이 파일을 돌려준다. `name`은 위 네 이름만 허용한다(경로 이동 방지). 없으면 404.
- `ScenarioSummary.cover`(이미지 주소 또는 `null`), `HintRecord.image`(이미지 주소 또는 `null`).

## 정한 것 (화면)
- 수신 기록: 어두운 바탕, 옅은 주사선, 위에서 아래로 6초에 한 번 흐르는 밝은 띠, 머리에 눈 로고 + "수신 기록" + "주시자와 연결됨" 신호 + 사용 막대.
- 답 색: 그렇단다 초록, 아니란다 빨강, 어느정도는 노랑, 중요하지 않단다 회색, 말해줄 수 없단다 회청색. 은은한 빛(`text-shadow`).
- 새로 들어온 줄(답, 계시, 추리 결과)만 0.8초 동안 깨진 글자가 맞춰지고 빨강·파랑 어긋남 1회. 페이지를 연 순간 이미 있던 줄은 그대로 보인다. `prefers-reduced-motion`이면 효과 없이 바로 보인다.
- 결과 도장: 해결 초록, 실패 빨강, 미해결 종결 회색, 이중 테두리 + 빛 + 주사선(시안대로).
- 이미지 자리:
  - 전체 배경 `frontend/public/backgrounds/room.webp`(있으면 어둡게 깔고, 없으면 지금 배경색).
  - 사이트 상징 `frontend/public/brand/logo.webp`(있으면 머리말 로고로, 없으면 지금 육각형 SVG). 탭 아이콘은 `frontend/public/favicon.svg`를 바꾸는 것으로 따로 한다.
  - 기본 사건 표지 `frontend/public/covers/default.webp`(문제별 `cover`가 없을 때. 이것도 없으면 표지 자리를 숨긴다).
  - 사건 목록 카드와 사건 기록 위쪽에 대표 이미지, 계시 줄 안에 힌트 이미지.

## 만드는 사람에게 맡기는 것
- 효과의 정확한 색·속도·크기(시안을 기준으로).
- 이미지의 크기와 잘라 보이는 방식, 좁은 화면 배치.

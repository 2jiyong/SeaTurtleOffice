# 4단계 EC2 배포 + HTTPS 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `https://www.seaturtleoffice.site`에서 게임이 돌고, `stats.`에서 Umami를 보며, 서버에서 `deploy/deploy.sh` 한 줄로 배포한다.

**Architecture:** EC2 한 대에 docker compose(`compose.prod.yaml`)로 caddy·backend·ai·postgres·umami를 띄운다. 이미지는 서버에서 직접 빌드(방식 A). Caddy가 인증서·정적 프론트·`/api` 프록시·요청 제한을 맡는다.

**Tech Stack:** Docker / compose v2, Caddy 2 + caddy-ratelimit(xcaddy), eclipse-temurin 25, python 3.12 + uv, node 22, postgres 17, Umami(postgres 판), AWS CLI(EC2·CloudWatch·SNS).

**Spec:** `docs/superpowers/specs/2026-11-27-deploy-design.md`

## Global Constraints

- 사용자에게 보이는 글, 커밋 메시지, 문서는 한국어. 커밋 끝에 Co-Authored-By / Claude-Session 줄.
- 비밀 값(OpenAI 키, DB 비밀번호, `IP_HASH_SECRET`, Umami `APP_SECRET`, 경보 메일 주소)은 저장소에 넣지 않는다. 저장소는 공개.
- 배포 compose 프로젝트 이름은 `sea-turtle-office-prod`. 개발 컨테이너 `sea-turtle-office-postgres-1`과 그 볼륨은 절대 건드리지 않는다(`docker stop`·`down`·`volume rm` 금지).
- 원본 IP를 로그·DB에 남기지 않는다(Caddy 접속 로그 끔).
- 돈이 드는 AWS 생성·변경·삭제는 명령과 비용을 보여 주고 사용자 허락 뒤에만. 조회는 자유.
- 도메인: 사이트 `www.seaturtleoffice.site`, 앞 도메인 `seaturtleoffice.site`(→ www 301), 통계 `stats.seaturtleoffice.site`.
- 요청 제한: 판정 경로 IP당 분당 60회, 그 밖 `/api/*` 분당 120회, 429 본문 `{"detail":"요청이 너무 잦습니다. 잠시 뒤 다시 시도해 주세요."}`.
- 메모리 상한: backend 640m, ai 256m, postgres 384m, umami 320m, caddy 128m. 로그 `json-file` 10m × 5.

## Review Focus

1. 루트 빌드 위치에서 `ai/.env`(실제 키)가 이미지로 새지 않는가 — Task 3에서 이미지 안을 직접 확인.

3. 시나리오만 바꾼 배포 뒤 ai·backend가 새 내용을 읽는가 — Task 4에서 `--force-recreate` 확인.
4. Umami 미설정·차단 시 프론트가 깨지지 않는가 — Task 1 테스트.
5. 첫 배포 때 DNS가 퍼지기 전에 Caddy를 켜서 인증서 발급이 막히지 않는가 — Task 6 순서.

- [ ] **Step 2: Caddyfile** — 설계 "Caddy" 절 그대로. 핵심:
  ```
  {
  	order rate_limit before basicauth
  }
  {$APEX_DOMAIN} { redir https://{$SITE_DOMAIN}{uri} permanent }
  {$STATS_DOMAIN} { reverse_proxy umami:3000 }
  {$SITE_DOMAIN} {
  	header { Strict-Transport-Security "max-age=31536000"; X-Content-Type-Options nosniff; Referrer-Policy strict-origin-when-cross-origin; -Server }
  	rate_limit { zone judge { match { method POST; path_regexp ^/api/games/[^/]+/(questions|guesses)$ } key {remote_host} events 60 window 1m } zone api { match { path /api/* } key {remote_host} events 120 window 1m } }
  	handle /api/* { header Cache-Control no-store; reverse_proxy backend:8080 { header_up X-Request-Id {http.request.uuid} } }
  	handle { root * /srv; header /assets/* Cache-Control "public, max-age=31536000, immutable"; header /index.html Cache-Control no-cache; file_server }
  	handle_errors 429 { header Content-Type application/json; respond `{"detail":"요청이 너무 잦습니다. 잠시 뒤 다시 시도해 주세요."}` 429 }
  }
  ```

### Task 6: AWS 자원 만들기와 첫 배포 (사용자 확인 필요)

코드가 아닌 운영 절차다. **각 묶음마다 명령·비용을 보여 주고 허락받은 뒤 실행.** 결과 ID는 대화에만 두고 저장소에는 넣지 않는다.

- [ ] **6-1 (무료):** 키 페어 `seaturtle-office` 생성 → `~/.ssh/seaturtle-office.pem` 권한 400. 보안 그룹 `seaturtle-office`(기본 VPC) + 규칙(80/443 tcp, 443 udp 전체; 22 현재 IP/32).
- [ ] **6-2 (월 약 $21):** AMI = `aws ssm get-parameters --names /aws/service/canonical/ubuntu/server/24.04/stable/current/arm64/hvm/ebs-gp3/ami-id`. `run-instances`: `t4g.small`, `--credit-specification CpuCredits=standard`, gp3 20GB, `HttpTokens=required`, `--disable-api-termination`, 태그 `Name=seaturtle-office`. Elastic IP 할당·연결.
- [ ] **6-3 (사용자):** 가비아 DNS에 A 레코드 `@`, `www`, `stats` → Elastic IP. `dig +short`로 세 이름 모두 확인될 때까지 기다림.
- [ ] **6-4:** SSH 접속 → `bootstrap.sh` → 서버 `.env` 작성(비밀은 서버에서 `openssl rand -hex 32`로 만들고, OpenAI 키는 사용자가 직접 붙여 넣음 — 대화에 키를 쓰지 않는다) → `deploy.sh`.

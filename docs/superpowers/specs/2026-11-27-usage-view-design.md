# 5단계: 사용량 보기 설계 (작은 변경)

## 왜
오늘 몇 명이 썼고 토큰(돈)을 얼마나 썼는지, 버전마다 응답이 빨라졌는지를 한눈에 본다. 혼자 보는 숫자이고 방문자 그래프는 Umami에 이미 있다.

## 방식 (사용자 결정: A)
- A. 터미널 명령 하나(선택): 내 컴퓨터에서 `deploy/usage.sh [일수]` → SSH로 서버 DB에 읽기 쿼리, 표 출력. 서버에 아무것도 더하지 않는다.
- B. 사이트 안 관리자 페이지: 휴대폰으로 볼 수 있지만 API·인증·화면이 다 필요하다.
- C. Grafana: 그래프는 좋지만 2GB 서버에 메모리 100~200MB, 공개 로그인 화면이 하나 더 생긴다.

## 내용 (날짜는 한국 시간 자정 기준, 기간 기본 7일)
- 오늘: 기기(이벤트를 남긴 client_id 수), 새 판(game_started), 질문·추리(ok), 힌트, 해결·미해결(game_ended의 status), 비용, 예산($2).
- 날짜별: 기기, 판정(질문+추리, limited 제외), 비용, 응답 p50/p95(total_ms, ok만), 오류(judge_error+timeout), 한도초과(limited).
- 버전별: 버전·모델, 판정(ok), p50/p95, LLM p50, 평균 입력/출력 토큰.
- 사건별: 시작, 해결, 해결률, 해결한 판의 평균 사용 횟수.
- 비용 = (입력-캐시)×0.25 + 캐시×0.025 + 출력×2.0 (100만 토큰당 달러). 한도(UsageLimiter)와 같은 대상(질문·추리, limited 제외)과 단가. 단가를 바꾸면 SQL도 고친다.

## 파일
- `deploy/usage.sql`, `deploy/usage.sh`(주소·키 기본값, 환경 변수로 바꿈), `deploy/usage-test.sh`(일회용 postgres에 V1~V3 + 정해 둔 이벤트, 숫자·자정 경계 검사), `DEVELOPMENT.md` 사용법.

## 하지 않는 것
그래프, 휴대폰 보기, 질문 원문(저장하지 않음).
